# Scenario: quick

The user wants food on the table within a time limit.

## Time limit

- The limit is **total time**: from the moment the user starts until the food
  is ready to eat.
- If the user doesn't give a limit, use the default from `profile/settings.md`
  (30 minutes if not set), and **say so explicitly**: "Assuming about 30 minutes."
- **Variant: limited hands-on time.** The user can be busy for only a set time,
  but the dish can take longer overall (e.g. "20 minutes of work, dinner in an
  hour"). Here the limit applies to active time, and total time is the second
  constraint.

## Count everything

Include every step that takes time: defrosting, soaking, marinating, preheating
the oven, boiling a large pot of water, resting. If nothing fits the limit, say
so. Never shrink an estimate to make a dish fit.

Cleanup is not counted, unless the person's preferences say it should be.

## Make it fast

- **Parallel steps:** give an order of work, not just a list of steps. For example:
  water on first, chop while it heats, sauce while the pasta cooks.
- **Equipment:** prefer what saves time in this kitchen (pressure cooker,
  microwave, kettle for boiling water, thin pans).
- **Keep it simple:** few components, techniques the user is comfortable with,
  little that needs constant watching. Not the time to learn something new.
- **Shortcuts** (canned, frozen, store-bought): fine if they're in the pantry and
  not against the person's preferences.
- **Calibrate** using `profile/log.md`. If the user is consistently slower or
  faster than estimates, adjust.

## Shopping

Assume no shopping by default. Ask only if nothing reasonable can be made from
what's at home.
